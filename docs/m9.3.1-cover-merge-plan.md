# M9.3.1 封面缓存与可撤销重复书合并设计

## 目标与边界

M9.3 已经具备分组、标签、批量编辑和只读重复候选预览。下一步不能直接加入“自动删除重复书”：现有 `books`、`chapters` 和 `image_sequences` 之间存在外键、阅读进度和本地目录状态，任何不带回滚的删除都可能破坏阅读历史或图片序列。

本设计先固定两个边界：

1. 封面显示使用“来源元数据 + 本机缓存”两层模型，缓存损坏、路径失效或网络不可用时不影响书籍正文。
2. 重复书合并必须是用户明确选择、可预览、可中止、可撤销的事务；首个实现只归档和建立别名，不物理删除原始书籍或章节。

本设计不引入脚本执行、不绕过站点访问控制、不默认下载远程封面，也不把图片序列页强行拼接为文本章节。

## 封面缓存策略

### 来源与权限

封面来源分为三类：

- `local_path`：用户选择或导入的本地绝对路径。保存前再次规范化，拒绝相对路径、越界路径、控制字符和 Windows ADS 片段。
- `remote_url`：仅接受 `https`（开发夹具可使用受控 `http`），默认不自动抓取；用户点击“刷新封面”后才发起单次请求。
- `none`：没有来源，使用内置的翻开书籍占位图。

远程封面不保存 Cookie、Authorization、Referer 或任意自定义敏感请求头；不把带查询参数的 URL 直接写入日志。远程请求复用书源 HTTP 边界：超时、重定向次数、响应体和 MIME 均有上限，非图片响应直接拒绝。

### 数据与缓存键

现有 `books.cover_path` 暂时作为兼容字段；M9.3.1 设计迁移 `0015_book_covers.sql`，增加：

- `book_covers(book_id, source_kind, source_value, source_fingerprint, cache_key, state, mime, width, height, byte_size, fetched_at, last_error, updated_at)`；
- `source_kind` 只能是 `none`、`local_path`、`remote_url`；
- `state` 只能是 `missing`、`stale`、`ready`、`blocked`；
- 每本书最多一条当前来源记录，历史失败信息只保留有限长度，不保存凭据。

缓存键使用版本化 SHA-256：

- 本地文件：`cover-v1\nlocal_path\nfile_size\nmodified_at_ns\ncontent_digest_if_known`；
- 远程文件：`cover-v1\nremote_url\netag_or_last_modified\ncontent_digest_if_known`；
- 没有可复用验证信息时，首次读取内容计算摘要；路径或响应验证器变化只标记 stale，不覆盖旧缓存。

缓存文件写入 Tauri 应用缓存目录的 `covers/<cache_key>.bin`，先写同目录临时文件并 `sync_all`，再原子 rename。单个封面上限 8 MiB，总缓存上限 256 MiB，清理按最近访问时间和状态排序；清理失败不影响书架读取。

### 读取与界面行为

- 书架只读取 `ready` 且缓存文件存在、大小和 MIME 通过校验的封面。
- 文件不存在、大小/修改时间变化或缓存摘要不一致时显示占位图并标记“封面需刷新”，不阻塞打开正文。
- 远程封面失败显示可操作的错误原因和“重试”，不在后台无限重试。
- CSP 只允许应用资源协议和已验证的本机缓存路径；UI 不直接加载任意远程 URL。
- 用户替换封面时，新缓存成功后才切换当前来源；失败则保留旧封面和旧来源。

### 封面验收标准

- 本地中文路径、UNC 路径、文件移动、文件替换和无权限目录均有测试；
- PNG/JPEG/WebP/GIF 的 MIME、尺寸、8 MiB 单文件和 256 MiB 总量边界有测试；
- 临时文件、进程中止、损坏缓存和重复刷新不会留下不可读的“ready”记录；
- 远程默认不请求；显式刷新时覆盖超时、重定向、非图片、超体积和离线错误；
- 书架、首页、重复候选面板在封面失效时都能回退到占位图。

## 可撤销重复书合并模型

### 选择与预览

合并入口只接受当前重复候选组中的 2—8 本书。用户必须显式选择“保留书籍”；系统不按更新时间自动决定。预览返回：

- 保留项和将被归档的书籍；
- 章节数量、标题冲突、内容摘要相同/不同；
- 阅读进度、当前章节、分组、标签、封面和自定义顺序的候选来源；
- 图片序列状态、根目录和页数冲突；
- 将要写入的别名、归档标记和可撤销期限。

预览带 `preview_id`、创建时间和输入指纹；提交前重新查询并校验指纹，候选变化、书籍被删除或预览超过 5 分钟时拒绝提交。

### 数据模型（0016 设计）

建议新增：

- `book_merge_operations(id, preview_id, canonical_book_id, status, plan_json, created_at, committed_at, undone_at, undo_until)`；
- `book_merge_items(operation_id, source_book_id, canonical_book_id, source_snapshot_json, appended_chapter_ids_json)`；
- `book_aliases(alias_book_id PRIMARY KEY, canonical_book_id, operation_id, created_at)`；
- `books.lifecycle_state`（`active`、`merged`），并为 `lifecycle_state = 'active'` 建索引。

原始书籍、章节和图片序列保留；`merged` 书籍从普通书架查询隐藏，但可从“合并记录”中查看和撤销。别名解析只允许单跳并检测环路，打开旧书籍 ID 时跳转到 canonical ID。

### 默认合并规则

- **章节**：默认保留 canonical 的章节顺序；来源书籍中标题与内容摘要都不相同的章节追加到末尾，并记录新增章节 ID。标题相同但内容不同的章节只进入冲突清单，不覆盖任何内容。
- **进度**：预览中由用户选择 canonical、最高进度或指定来源；默认推荐 canonical，绝不静默覆盖。
- **分组/标签**：分组默认使用 canonical，canonical 为空时才建议使用来源值；标签取去重后的并集，保留用户可编辑结果。
- **封面**：优先保留 canonical 的 ready 封面，否则从明确选择的来源复制来源元数据；不自动下载远程封面。
- **图片序列**：只要参与项包含 `image_sequence`、根目录不同或页级状态非 ready，就阻止默认合并，要求用户明确“只保留某一序列”；不拼接、覆盖或删除页记录。
- **自定义顺序**：保留 canonical 值；归档项的排序值只写入快照。

### 事务、回滚与保留期限

提交时在一个 SQLite 事务内：

1. 再次检查 `preview_id` 和每本书的输入指纹；
2. 写入操作记录和每个来源的快照；
3. 按预览计划合并元数据、追加无冲突章节并写入别名；
4. 将来源书籍标记为 `merged`，不执行物理删除；
5. 更新 canonical 的 `updated_at`，提交后返回新的书籍摘要和冲突清单。

任一步骤失败都回滚。撤销操作在 `undo_until`（默认 7 天）内可执行：恢复元数据、删除本次新增章节、移除别名并将来源书籍恢复为 `active`；撤销也必须是事务。超过期限的操作仍保留审计记录，但不自动清除原始数据，后续再设计显式清理工具。

### 安全闸门

- 不提供“全部重复书一键合并”；
- 每次最多 8 本书，章节追加和快照大小有配额；
- canonical、章节进度来源、图片序列处理方式必须明确；
- 任何冲突默认阻止提交而不是猜测；
- 诊断日志只记录 operation_id、数量和状态，不记录正文、封面二进制或敏感 URL。
