# M7.4 JavaScript 评估安全闸门

状态：设计闸门，当前版本不执行 JavaScript。

本文件用于把“是否允许书源脚本进入 Windows 版”拆成可审计、可回滚的条件。任何一个条件未满足，都保持“可导入但不执行”，不能因为规则看起来简单就静默降级成 CSS 或直接运行。

## 当前决策

- `@js`、`webJs`、`js:`、`javascript:` 和脚本型 `contentRule` 继续明确拒绝执行。
- 导入预览保留有限的原始规则、上下文和拒绝原因；诊断导出不包含脚本正文、Cookie、认证头、关键词、书籍/章节 ID 或响应正文。
- M7.4 只允许合成输入和离线验证，不连接真实书源，不执行用户导入的未知脚本。
- 运行时、依赖许可证和发布策略未定案前，不增加“实验性执行”开关。

## 必须先关闭的八道闸门

### 1. 许可证与供应链

- 逐项记录候选 JavaScript 引擎、绑定库及其传递依赖的许可证、版权声明、NOTICE 和发布限制。
- 依赖版本必须锁定并可复现；安全公告、撤销版本和升级负责人要有记录。
- 不复制 Android 项目的脚本运行时代码；兼容行为只参考公开协议和合成夹具。
- 若许可证、分发义务或维护状态无法确认，直接淘汰候选。

### 2. 隔离边界

- 脚本运行在独立 worker/进程边界，不与 Tauri 主进程共享可变状态。
- 默认无文件、进程、系统命令、剪贴板、注册表、窗口控制和任意环境变量访问。
- 网络访问不由脚本直接发起；只有经过 Rust 请求代理、来源权限和同源策略校验的显式 API 才能使用。
- 运行时崩溃、拒绝服务或超时必须只影响当前任务，不能拖垮阅读器主进程。

### 3. 资源配额

- 每次执行有硬性墙钟超时、CPU 时间、最大堆、最大调用深度、最大输出字节数和最大日志条数。
- 配额耗尽统一返回稳定的 `script_budget_exceeded` 原因，并取消后续网络/解析步骤。
- 配额按一次规则执行和整条书源 pipeline 分层统计，不能在分页或重试时重置。
- 需要离线压力夹具证明：深递归、死循环、超大字符串、对象爆炸和连续请求均能在上限内结束。

### 4. API 白名单

- 先定义版本化、最小化的只读 API：输入快照、受限变量、显式 HTTP 代理和取消信号。
- API 参数经过 URL、响应大小、重定向、同源/允许主机和敏感请求头审计；脚本不能拼接绕过校验的请求。
- 禁止动态加载模块、反射访问宿主对象、原生 FFI、任意 `eval`/`Function` 扩权和隐藏通道。
- 每个 API 调用都应能在诊断时间线中记录名称、结果类别和耗时，但不记录秘密值。

### 5. 数据与隐私

- 脚本输入只包含当前请求所需的最小字段；Cookie、Authorization、代理凭据和本地路径默认不注入。
- 日志、错误、崩溃报告和导出快照均需脱敏，不能回显脚本原文或响应正文。
- 书源作者和用户必须能看到“脚本会调用哪些白名单能力”，并能在保存前取消。

### 6. 用户授权与可见开关

- 全局默认关闭；首次启用前显示风险、许可证和权限说明。
- 以书源为粒度授权，界面显示能力徽标、最近执行结果、配额和撤销入口。
- 关闭开关后立即阻止新执行；正在运行的任务使用取消 token 终止。
- 导入、更新和恢复配置不能悄悄重新打开脚本执行。

### 7. 回滚与故障处理

- 脚本能力必须由独立 feature flag 控制，关闭后保留导入数据和拒绝原因。
- 运行时升级、策略变更或发现漏洞时，可以通过配置迁移和远程发布闸门一键撤销。
- 任何异常都要回到“可导入但不执行”，不能自动尝试另一种脚本引擎或 CSS 降级。
- 诊断结果需要区分：未授权、能力不支持、超时、超内存、API 拒绝、运行时崩溃和用户取消。

### 8. 可验证性

- 先建立离线合成夹具：正常脚本、死循环、递归、超大输出、越权 API、跨源请求、敏感头读取、崩溃和取消。
- 每个夹具都要断言：返回码、取消时延、资源上限、主进程存活、日志脱敏和数据不变性。
- CI 只运行固定夹具，不访问真实站点；发布前必须有 Windows runner 的隔离/卸载/回滚证据。
- 安全审查、依赖审查和兼容性矩阵必须在同一提交中留痕。

## 建议的验证顺序

1. 许可证与依赖清单：只做静态审计，不引入运行时。
2. 独立 worker 的最小 PoC：只执行内置常量表达式，不加载书源脚本。
3. 资源配额和取消夹具：证明超时、内存、输出和崩溃不会影响主进程。
4. API 白名单模拟器：只返回合成数据，验证 URL/权限/脱敏边界。
5. 用户授权与 feature flag：默认关闭、按源授权、撤销和配置迁移。
6. Windows CI 安全回归：隔离、日志、安装/卸载、回滚和产物检查。
7. 经过代码审查和许可证确认后，才讨论是否开放极小的实验性兼容子集。

## 退出条件

在上述八道闸门和验证顺序全部有证据之前，M7.4 不得标记为“可执行”。当前路线图保持：

> JavaScript 书源：可导入但不执行；XPath：仅静态识别和离线 PoC；CSS/JSONPath/正则：按已实现安全子集执行。

## 与后续 M7.5 的关系

M7.5 可以在不执行脚本的前提下继续完善请求/解析/缓存诊断、重试原因、导入 diff 和版本迁移。诊断模型必须预留脚本拒绝与配额错误的稳定枚举，但不需要安装 JavaScript 运行时。
