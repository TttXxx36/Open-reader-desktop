# M9.3.1-d3 撤销与旧 ID 兼容契约

## 目标与范围

d3 只处理 d2 已提交的纯文本、无正文冲突合并记录。它不引入物理删除，不自动选择 canonical，也不把图片序列、远程封面或脚本能力纳入撤销范围。

## 撤销语义

- 每次 d2 提交的 `book_merge_operations` 保留 7 天撤销窗口；状态只能从 `committed` 转为 `undone` 或 `expired`。
- 撤销必须在一个 SQLite 事务中完成：校验操作状态和窗口、校验 canonical/来源书籍没有外部变化、删除本次追加章节、恢复 canonical 合并前的元数据/阅读状态、恢复来源为 `active`、删除本次 alias，最后写入 `undone_at`。
- 任何校验失败都不写入；窗口过期只把操作标记为 `expired`，不清理原始书籍或章节。
- 外部变化以可比较字段判断：canonical 的标题/作者/格式/内容类型、原有章节标题与正文摘要、合并后元数据/进度、追加章节内容，以及来源书籍的生命周期和快照。发现变化时拒绝撤销，不覆盖用户数据。

## 旧 ID 解析

- 旧书籍 ID只允许一跳解析到 canonical；普通详情、章节内容和阅读进度命令使用解析后的 canonical ID。
- 如果目标本身仍是 alias，视为多跳链并拒绝；如果 alias 指向自身或形成回指，报告别名环路并拒绝。
- `resolve_book_alias` 提供可观测结果（请求 ID、canonical ID、是否重定向、跳数），供界面显示和回归测试使用。

## 验证与边界

- Rust 夹具覆盖成功撤销、重复撤销、过期撤销、canonical/来源外部修改拒绝、追加章节被修改拒绝、旧 ID 单跳解析和 alias 环路/多跳拒绝。
- d3 不改变默认书架的 `active` 过滤，不恢复已被其他后续操作改变的数据；这类场景必须重新生成合并预览。
- 真实 Windows UI 不在本轮自动验收范围；后端切片通过 GitHub Actions 后，再随合并后 Windows 产物补做人工回归。
