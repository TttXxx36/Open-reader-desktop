# Windows 验收缺陷修复记录（v0.2.0）

本轮针对目标 Windows 验收中发现的高优先级缺陷进行一次性修复，并通过 GitHub Actions 远程构建安装版与便携版；不在开发机执行安装。

## 已修复问题

| 优先级 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| P0 | 在线搜索结果点击后提示 `bookInfoUrl is required` 或无反应 | 搜索结果没有携带书源的详情/目录/正文能力，界面仍把“仅搜索”结果渲染为可打开按钮；旧运行时也会在缺少规则时才发现配置错误 | 后端为每条结果返回 `can_open`、`can_read` 和 `unavailable_reason`；前端仅对完整能力结果启用整行点击，并保留清晰的“仅搜索”状态；详情、目录和正文规则检查提前到网络请求前；缺少 URL 时继续使用结果页/章节页回退地址 |
| P1 | 阅读到章节末尾后进度仍为 0%，重新打开回到顶部 | 进度只按章节索引计算，未记录滚动位置，也没有读取恢复位置 | 新增 SQLite 迁移 `0017_reading_state`，保存滚动偏移、已读状态和更新时间；滚动停止后去抖写入，打开书籍时恢复位置；单章节按滚动比例计算进度 |
| P2 | 无法明确标记已读/未读 | 阅读模型没有显式状态 | 阅读器底部增加“标记已读/标记未读”，状态与进度同时持久化 |
| P2 | 大型在线书源集合被 16 MiB 限制拦截 | 前端、后端和快照层使用旧的 16 MiB 限制 | 本地/在线导入、在线导入响应和导入前快照统一提升为 128 MiB，并同步错误提示与文档 |

## 兼容性边界

书源仍不会执行 JavaScript、XPath、Cookie 或 Authorization 等高风险规则。只有包含可解析详情、目录和正文规则的结果才会进入阅读链路；纯搜索书源会被保留并标记为“仅搜索”，不会再以点击失败的方式打断用户。

## 验证门禁

1. `npm run typecheck`、`npm run build`、UI contract 和 `npm run verify:release:strict` 在 Windows Release 工作流中通过。
2. Rust fmt/check/test 覆盖新迁移、进度写入与书源能力字段。
3. Release workflow 生成 NSIS、MSI、便携 ZIP 和 `release-sha256.txt`；installer smoke 继续校验启动、安装/卸载、校验和与数据保留。
4. 目标 Windows 人工验收重点复测：在线搜索结果点击、详情/正文加载、滚动后重开恢复、已读/未读切换和超过 16 MiB 的书源集合导入。
