## 背景

项目借鉴了 Android 阅读软件的产品思路，但不直接复制未确认许可证的代码、资源或版权内容。仓库同时需要明确原创代码许可证、书源 JSON 的安全兼容范围、网络访问权限和贡献者责任，避免把“能导入”误解为“能安全执行”或“内容已获授权”。

## 决策

### 1. 项目许可证

- 仓库原创代码与文档采用 MIT License，完整文本见根目录 [LICENSE](../../LICENSE)。
- 第三方依赖、字体、图标、示例、测试素材和未来引入的外部代码不自动获得 MIT 许可；必须保留原许可证、归属和 NOTICE 要求。
- 未经许可证核对，不复制 legado/阅读或其他项目的源代码、资源、书源集合或版权正文。
- 贡献者必须有权按 MIT License 提交其变更；涉及第三方内容时，PR 必须附许可证和归属说明。

### 2. 内容与书源边界

- 不内置未经授权的版权书源或书籍，不绕过登录、付费、验证码、DRM 或其他访问控制。
- 测试只使用用户自有、已授权、公开测试或公版内容；真实站点验证必须先确认授权和服务条款。
- `permission` 元数据只记录用户提供的状态、范围和复核时间，不是项目对授权真实性的证明；缺失或未知记录必须提示。

### 3. 兼容性分层

| 层级 | 规则 | 行为 |
| --- | --- | --- |
| 可执行 | HTTP(S)、CSS/JSoup、正则和受限 JSONPath | 在配额、超时、响应体、重定向和取消边界内执行 |
| 可导入但不执行 | XPath、JavaScript、模板脚本、未实现扩展、认证态元数据 | 保留可审计原始值并显示不执行原因，不静默改写为 CSS 或匿名请求 |
| 明确拒绝 | 本机文件/进程/命令、敏感 Cookie/Authorization 自动注入、绕过访问控制、音频执行和危险脚本 | 阻止保存或执行，并给出可操作提示 |

“导入成功”只表示配置通过结构和安全闸门，不代表站点可访问、内容已获授权或所有规则可执行。

### 4. 网络与隐私

- 所有远程书源请求经 Rust 受限客户端发起；仅允许 HTTP(S)，并受超时、响应体、重定向、并发、缓存和取消限制。
- 不自动携带 Cookie、Authorization 或 Proxy-Authorization；如未来支持，必须使用 Windows 安全存储、逐源授权和脱敏审计。
- 日志、诊断导出和缓存状态不得包含完整敏感 URL 参数、请求头或正文；默认不收集遥测。

### 5. 维护与验收

- README、CONTRIBUTING、SECURITY、compatibility-matrix、product-scope 和 source-protocol 的政策表述必须链接本 ADR。
- 每个新增兼容字段都要有授权/合成夹具、拒绝用例和兼容矩阵记录。
- Issue #1 在治理文档合并、远程 CI 通过且链接检查完成后关闭；后续规则运行时另开 ADR 和安全评审。
