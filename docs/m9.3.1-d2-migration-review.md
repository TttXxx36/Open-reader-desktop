# M9.3.1-d2 迁移前评审记录

> 状态：已实现并通过远程 CI；P0 Windows 手工验收记录见 [2026-08-21 验收记录](windows-manual-acceptance-2026-08-21.md)。
> 关联设计：[M9.3.1 封面缓存与可撤销重复书合并设计](m9.3.1-cover-merge-plan.md)。  
> `0016` 已接入迁移链路；d2 仍不提供物理删除、撤销按钮或自动选择 canonical 的 UI 入口。

## 评审结论

d2 首版只支持纯文本书籍的显式合并：

- 每次 2—8 本，必须明确指定 canonical 书籍；
- 章节正文无冲突时，才允许追加“新标题”章节；
- 图片序列、章节正文冲突、远程封面、缺失/过期图片状态和超出配额时默认阻止；
- 原书籍和原章节始终保留，只把来源书籍标记为 `merged` 并建立单跳别名；
- 所有写入必须在一个 SQLite 事务中完成，任何失败整体回滚；
- d2 不实现撤销按钮；撤销语义留给 d3，但 d2 必须保存足够的来源快照和新增章节 ID。

## 0016 schema 冻结

迁移文件为 `src-tauri/migrations/0016_book_merge.sql`，版本号为 16。

### `books.lifecycle_state`

- 新增 `lifecycle_state TEXT NOT NULL DEFAULT 'active'`；
- 允许值：`active`、`merged`；
- 为 `(lifecycle_state, updated_at DESC)` 建索引；
- 现有数据默认全部为 `active`；
- 普通书架、搜索、重复候选和首页查询必须显式加 `lifecycle_state = 'active'`；
- d2 不修改 `path`、正文和图片序列记录。

### `book_merge_operations`

字段固定为：

- `id TEXT PRIMARY KEY`：`merge-operation-` 前缀；
- `preview_id TEXT NOT NULL UNIQUE`：防止同一预览重复提交；
- `canonical_book_id TEXT NOT NULL`；
- `status TEXT NOT NULL`：`committed`、`undone`、`expired`；
- `plan_json TEXT NOT NULL`：只保存最终策略和 ID，不保存正文、封面二进制、Cookie、Authorization 或敏感 URL；
- `created_at TEXT NOT NULL`、`committed_at TEXT NOT NULL`、`undo_until TEXT NOT NULL`；d3 的 `undone_at` 尚未加入；
- `FOREIGN KEY(canonical_book_id) REFERENCES books(id) ON DELETE RESTRICT`。

约束：

- `plan_json` 最大 64 KiB；
- d2 提交后状态为 `committed`，`undo_until` 为提交时间加 7 天；
- 不允许删除操作记录。

### `book_merge_items`

每个来源书籍一行：

- `operation_id TEXT NOT NULL`；
- `source_book_id TEXT NOT NULL`；
- `canonical_book_id TEXT NOT NULL`；
- `source_snapshot_json TEXT NOT NULL`：元数据、进度、分组、标签、封面来源摘要和章节 ID/摘要；
- `appended_chapter_ids_json TEXT NOT NULL DEFAULT '[]'`；
- 主键为 `(operation_id, source_book_id)`；
- 来源和 canonical 均使用 `ON DELETE RESTRICT`；
- `source_book_id` 不得等于 `canonical_book_id`。

约束：

- 单个来源快照最大 256 KiB；
- 新增章节 ID 列表最多 512 项；
- 不保存章节正文副本，正文仍由新增章节记录保留。

### `book_aliases`

- `alias_book_id TEXT PRIMARY KEY`；
- `canonical_book_id TEXT NOT NULL`；
- `operation_id TEXT NOT NULL`；
- `created_at TEXT NOT NULL`；
- 主键和 canonical/来源索引已建立；
- `alias_book_id` 不得等于 `canonical_book_id`；
- `ON DELETE RESTRICT`，d2 不允许通过级联删除别名；
- d2 只生成单跳别名，环路检查保留给 d3。

## 提交事务边界

提交命令必须接收预览二次校验所需的全部字段：

`preview_id`、`created_at`、`expires_at`、`input_fingerprint`、候选书籍 ID、canonical ID、进度来源 ID，以及最终分组和标签。

事务内按以下顺序执行：

1. 校验 preview ID、有效期和输入指纹；重新查询每本书和章节摘要；
2. 拒绝已存在的 `preview_id`、已归档书籍、候选缺失、数据变化或超时预览；
3. 拒绝图片序列、远程封面、章节正文冲突、非纯文本内容和任何配额超限；
4. 写入 `book_merge_operations` 和 `book_merge_items`；
5. 按预览计划复制无冲突章节，生成 `merge-operation-...` 前缀的新章节 ID；
6. canonical 应用明确的最终标签/分组，并从请求指定的进度来源复制进度；调用方必须显式传入进度来源；
7. 将来源书籍更新为 `lifecycle_state = 'merged'`，建立单跳别名；
8. 提交事务并返回 canonical 摘要、归档 ID、追加章节 ID 和冲突清单。

任何一步返回错误，都必须回滚全部写入。实现中不得使用无条件 `DELETE FROM books`、`DELETE FROM chapters` 或覆盖来源正文的 SQL。

## 配额与安全边界

- 书籍数：2—8；
- 新增章节：最多 512；
- 合并计划 JSON：≤ 64 KiB；
- 单个来源快照：≤ 256 KiB；
- 单次新增章节正文总量：≤ 64 MiB；
- 单章正文：≤ 8 MiB；
- 仅接受 `content_kind = 'text'` 且格式已经通过现有导入边界；
- 日志只记录 operation ID、数量、状态和耗时，不记录正文或敏感来源信息。

## 必须先通过的 Rust 夹具

1. 迁移后旧数据库所有书籍为 `active`，重复/书架查询结果不变；
2. 成功合并：追加无冲突章节、写入操作/来源快照、来源变为 `merged`，canonical 仍可阅读；
3. 同一 `preview_id` 重复提交被拒绝，数据库无第二次变更；
4. 提交前修改书名、进度、章节或标签导致指纹变化时拒绝，数据库保持原状；
5. 章节正文冲突、图片序列、远程封面、非文本内容和超限输入均拒绝；
6. 任意一步模拟 SQLite 错误时，操作记录、章节、别名和生命周期状态全部回滚；
7. `ON DELETE RESTRICT` 阻止物理删除来源书籍、章节和操作记录；
8. 旧 ID 在 d2 只保持数据可查询，自动跳转和环路拒绝留给 d3。

## 现有代码影响审计

实现 `0016` 前必须逐项处理以下现有 SQL 面：

- 书架、重复候选、单本摘要和图片书架查询都要显式过滤 `lifecycle_state = 'active'`；不能只修改首页查询，否则归档书仍会在重复候选或详情入口出现。
- 当前本地导入会按 `path` 执行 `DELETE FROM chapters` 和 `DELETE FROM books`。d2 接入后，若路径对应已合并书籍，必须先返回“存在合并记录，请先撤销或更换路径”的可操作错误，不能触发物理删除或破坏 `ON DELETE RESTRICT`。
- 元数据、进度和图片序列写入命令应拒绝对 `merged` 书籍直接写入；旧 ID 自动跳转留给 d3，d2 不静默改写到 canonical。
- 新建文本书和图片序列书依赖 `lifecycle_state` 的默认值 `active`；迁移回归测试必须覆盖这两个插入路径。
- 现有测试中直接删除书籍的清理夹具需要在 d2 测试里改为先清理合并记录，或明确断言 `ON DELETE RESTRICT`；不得为了让旧夹具通过而放宽外键。
- `book_covers` 当前为 `ON DELETE CASCADE`，但只要书籍本身被 `ON DELETE RESTRICT` 阻止，d2 就不会因封面记录而发生隐式删除；撤销和 d3 清理必须显式处理缓存元数据。

## 当前禁止事项

在 d3 撤销契约完成前，继续禁止：

- 物理删除书籍、章节、图片序列或封面；

- 打开“全部重复书一键合并”。
