## 缺陷记录

每个失败项至少记录：

1. 编号、复现步骤和发生频率；
2. 预期与实际差异；
3. 截图/脱敏日志；
4. 是否涉及数据丢失、静默网络请求、脚本执行或权限越界；
5. 临时规避方式和建议优先级（P0/P1/P2）。

## 通过门槛

- P0 项目全部为“通过”，或明确记录为“阻塞”并给出外部原因；
- 不允许存在数据丢失、静默覆盖、未授权网络请求或脚本执行；
- 安装版、便携版和旧数据升级均有证据；
- 完成记录后，才允许进入 M9.3.1-d2 的 `0016` 迁移评审；
- d2 评审未通过前，不执行物理删除或自动合并。
